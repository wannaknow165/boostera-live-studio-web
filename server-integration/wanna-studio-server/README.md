# WANNA Studio Server

שרת אחד שמחזיק את **כל** מה שה-TikTok LIVE Studio צריך: גלריה, סרטוני תומכים (פרונט / רקע) ואפקטים חיים על המשדרת (רמיקס).
One server for everything the TikTok LIVE Studio needs. Zero npm dependencies — Node 20+ and ffmpeg/ffprobe on PATH.

## הפעלה / Run
```
node server.mjs          (או לחיצה כפולה על start.cmd)
```
| כתובת | מה זה |
|---|---|
| http://localhost:8800/ | **גלריה** — טבלה של כל האפקטים |
| http://localhost:8800/fx/ | **פאנל אפקטים חיים** — זיהוי פנים/גוף, רמיקס למשדרת, חיבור טלפון ADB |
| http://localhost:8800/health | מצב השרת |

## מה יש בגלריה (4 סוגים)
| סוג | מה זה | קובץ | ב-Studio |
|---|---|---|---|
| 🟣 **פרונט** | מתנה שקופה מעל המשדרת (סרטון תומך) | WebM עם שקיפות | Overlays → `srv_ov_<id>` |
| 🔵 **רקע** | סרטון מלא שמחליף את המסך (סרטון תומך) | MP4 | Videos → `srv_clip_<id>` |
| 📋 **תבנית** | סרטון בסיס שהתומך נכנס אליו (תפריט ללקוח) | MP4 | — |
| 🟠 **אפקט חי** | המשדרת עצמה משתנה (רמיקס AI מהפריים שלה) | MP4 לכל משדרת | Videos → `srv_clip_remix-<effect>-<streamer>` |
| 🖼 **חדר** | רקע של אפקט (תמונה) | JPG | Background assets |

## חיבור ל-TikTok LIVE Studio
ב-`.env` של ה-Studio:
```
BOOSTERA_UPSTREAM_URL="http://localhost:8800"      # בייצור: הכתובת הציבורית של השרת
BOOSTERA_CLIENT_KEY="<אותו ערך כמו STUDIO_CLIENT_KEY כאן>"
```
ה-Studio מושך את הקטלוג כל 15 שניות ומציג אותו בספריית האפקטים שלו.
The Studio upstream API implemented here:

| Studio קורא ל- | מחזיר |
|---|---|
| `GET /api/overlays` | `{ list: [{ id, he, kind, pos, size }] }` — מתנות פרונט |
| `GET /api/set` | `{ clips: [{id,name,file,thumb}], assets: { front: [...], bg: [...] } }` |
| `GET /media/overlays/<id>.webm` | קובץ הפרונט השקוף |
| `GET /media/...` | כל הקבצים והתמונות הממוזערות (`/media/_thumb?src=`) — ה-Studio מעביר רק `/media/*` |
| `POST /api/overlay/play {id,loop}` · `/api/clip/play {id}` · `/api/overlay/stop` · `/api/clip/stop` · `/api/desk/stop` | מצב "מה מתנגן" (+ זרם `GET /api/stage-events`) |
| `PUT /api/upload` `/api/fx/upload` `/api/overlay/upload` | סרטון → נכנס לגלריה כתבנית |
| `PUT /api/players/photo` | תמונה → תמונת תומך |

## סרטוני תומכים (Kling 4.0)
כותרת `x-api-key: <API_TOKEN>`.
1. `POST /api/avatars?name=דני` (גוף = תמונה) → `{ id }`
2. `POST /api/orders` `{ templateId, avatarId, mode: "replace"|"add", layer: "front"|"background", supporterName, callbackUrl }`
3. `GET /api/orders/<id>` → כשמוכן: `resultUrl` (רקע) / `transparentUrl` (פרונט)
- תבנית חדשה: לשים MP4 בתיקייה `media/inbox` (אופציונלי `<name>.json` עם `title, trimStart, trimEnd, character, layer`) — תוך 10 שניות היא בגלריה.
- Kling מוריד את סרטון התבנית מ-`PUBLIC_BASE_URL`, לכן בייצור השרת חייב כתובת https ציבורית.
- `GET /api/kling/units` — יתרת יחידות.

## אפקטים חיים (רמיקס)
- אפקט חדש מקישור טיקטוק: `node fx/builder/fx.mjs remix "<קישור>"` → כפתור בפאנל.
- בפאנל: שם המשדרת → "הכן רמיקס" (המשדרת מסתכלת למצלמה; ~4 דקות, ~1.1$ דרך OpenRouter) → נשמר לה לתמיד ומופיע גם ב-Studio.

## אוטומציות קרב (http://localhost:8800/automations)
כל אירוע בקרב מפעיל אפקט לבד. הכללים נשמרים ב-`data/automations.json` ונערכים בדף.
אירועים נכנסים ב-`POST /api/event` (מקורא המתנות / ה-Studio):
```
{"type":"battle_start","user":"<היריב>"}   {"type":"gift_x5","user":"<על מי>"}   {"type":"snipe","user":"..."}
{"type":"win"} {"type":"lose"} {"type":"lead"}   {"type":"gift","gift":"Lion"}   {"type":"supporter_gift","supporter":"דני"}
```
פעולות: קליפ אישי אקראי של היריב · קליפ קרב על השחקן (עם מיקום הפנים וזמני המכות) · אוברליי/דמות · אפקט חי על המשדרת (הפאנל /fx/ מאזין ומפעיל לבד, רמיקס אם מוכן) · סרטון רקע · הסרטון של התומך.
כל מה שמופעל מתפרסם ב-`GET /api/stage-events` (SSE) — שם ה-Studio והפאנל מקבלים אותו.

## על המסך: הגמד, WAKE UP, עגבניות
- הגמד נותן מכות למסך (×1 / ×2 / דאבל רץ), WAKE UP (צועק, כאפות, בום בסאונד והמסך רועד) — `/play/screen/hits|double|wake|stop`.
- **עגבנייה** — `/play/screen/tomato?count=1`, או אוטומטית: כל ורד (כלל r18) / יעד מטבעות (r19).
  - כשיש **קרב על מסך הטלפון**: הראש החי של המתחרה עולה על המסך **שלנו** והעגבניות נזרקות עליו.
    `&style=head` (או הבורר בפאנל) = הסגנון הקודם: העגבנייה עצמה בצורת הראש שלו, מתנפצת ונמרחת.
  - אין קרב → עגבנייה רגילה שמתנפצת על המסך.

## המטרה בקרב: הראש החי של מי שמולי
על המסך של המתחרה אי אפשר לצייר (הווידאו שלו שייך ל-TikTok). לכן הראש שלו נלקח **ממסך הקרב בטלפון** ומובא חי אל המסך שלנו.
- **מי המטרה:** אוטומטית **מי שמולי** (הראש הגדול בחצי הימני של מסך הקרב; היוצר/ת בצד שמאל). בקרב של ארבעה אפשר **לבחור ראש** בכרטיס "🎯 המטרה" בפאנל (לחיצה על אחת התמונות העגולות; "אוטומטי" מחזיר למי שמולי). הבחירה נשמרת בשרת (`POST /api/opponent-pick {pick:{fx,fy}|null}`) וכל הדפים הולכים אחריה.
- **מה נעשה בראש:** נגזר נקי (שיער ופנים, בלי החדר שמאחוריו, עד הסנטר) ומתעדכן חי (וידאו) כל זמן שאפקט צריך אותו.
- **קליפי הקרב** (`/play/battle/<id>` · אירועי האוטומציות · כפתורי הבדיקה בפאנל) — לפי `media/battle/heads.json`:
  | קליפ | מה קורה עם הראש |
  |---|---|
  | `snipe` | הראש שלו במקום הראש של הרקדן עם החצאית, בתוך כוונת הצלף; ירייה, זכוכית נשברת, קול "SNIPED!" |
  | `tomato` · `diaper` | הראש עולה כמדבקה והעגבנייה / החיתול נוחתים עליו |
  | `multiplier_x2` · `multiplier_x3` · `glove_x5` | הראש עומד משמאל לגמד והבעיטות / הסטירות / האגרופים נוחתים עליו. בדאבל הוא ממשיך להרביץ לו כל זמן שהדאבל רץ |
  | `dancer` · `baby_body` · `hand_mini` | הראש יושב על גוף הרקדנית / התינוק / האיש הקטן שבכף היד |
  בלי קרב על מסך הטלפון (או כשהמתג "להשתמש בראש החי של המתחרה" כבוי / `POST /api/opponent-face?enabled=0`) הקליפים מתנגנים כמו שהם.
- **פרטיות:** מסך הטלפון נבדק רק כש-TikTok פתוח בו (`?need=tiktok`): לפני כל תמונה ואחריה השרת שואל איזו אפליקציה מקדימה, ובזמן אפקט הוא שואל **כל שנייה**. יצאת מ-TikTok? הזרם נסגר מיד, ההקלטה נעצרת (אם אף אחד לא משקף את הטלפון בכוונה) והדף שוכח את התמונה ואת המטרה. מטרה חדשה נלקחת רק ממסך קרב אמיתי (ראש בשני הצדדים). **לשידור מצוירת רק תמונה שבה היריב זוהה בפועל** (בין שתי תצפיות של המעקב, ורק אם הפנים נראות כמו הראש שנראה רגע קודם), ולכן הראש מוצג באיחור של כשליש שנייה; אם הוא מוסתר לרגע או שהמסך מתחלף, הראש עומד במקום ואז נעלם. לא נשמר דבר מלבד תמונת פנים עגולה קטנה (`media/opponent/face.png`) שמתחלפת כל כמה שניות ונמחקת מהדיסק 50 שניות אחרי האחרונה, כשמכבים את המתג, ובהפעלת השרת.
- **סגנון העגבנייה** (על הראש החי שלו / עגבנייה בצורת הראש שלו) נשמר בשרת כמו המתג, כך שגם `/clean/foreground` וכל פאנל פתוח הולכים אחריו: `POST /api/opponent-face?tomatoStyle=live|head` (או הבורר בפאנל). קישור עם `&style=head` גובר.
- **קוד:** `fx/opponent.js` (מציאת הראש, מעקב, גזירה) · `fx/phone-stream-worker.js` (קריאת זרם הווידאו מהטלפון ופענוח התמונות מחוץ לדף: רק אזור הקרב, עד 20 תמונות בשנייה) · `fx/battle-stage.js` (ציור הקליפים עם הראש) — משותפים לפאנל ולשכבה `/clean/foreground`. המנוע (`fx/fx-engine.js`) נטען גם בלי שני המודולים האלה (למשל דרך שער המובייל שמגיש רק את המנוע): אז פשוט אין קליפי קרב.
- **בדיקה בלי טלפון:** `/fx/?oppsrc=<קובץ וידאו של מסך קרב>&oppRegion=x0,y0,x1,y1` (אזור הקרב על המסך; ברירת מחדל `0,0.15,1,0.63`) · `?oppsrc=<כתובת של phone.jpg אחר>` = טלפון מדומה (הזרם שלו `phone.mjpeg` לידו) · `?oppHost=0` = לא לדרוש ראש בצד שמאל · `?opp=0` = בלי מעקב בכלל. אותו דבר ב-`/clean/foreground`.
- **בדיקה אוטומטית של שער הפרטיות** (טלפון מדומה, בלי לגעת בטלפון האמיתי): `node --experimental-test-module-mocks --test test/phone-gate.test.mjs`.

## אפקט לתומך: התומך עצמו בתוך האפקט
כל אפקט לתומך משלב את **האווטאר של מי שנתן**: תמונת הפרופיל שלו נגזרת לראש (שיער ופנים, באותו מודל שגוזר את ראש היריב) ומשתלבת בזמן אמת בתוך קליפ מקורי שלנו. אין הפקה מראש לכל תומך ואין עלות: זה מצויר חי, לכל תומך ולכל מספר.
- **`fan_burst`** — טבעת זהב נטענת עם הראש שלו בפנים, ברקים, פיצוץ אש, והכפל בענק (`×2`, `×3`, `×50`, כל מספר), השם שלו מתחת, מטבעות יורדים. **`fan_mvp`** — אותו דבר עם **MVP**, כתר על הראש וגביעים (ניצחון).
- **קישור:** `/play/battle/fan_burst?user=<שם>&avatar=<כתובת התמונה>&mult=3` · `/play/battle/fan_mvp?user=<שם>&avatar=<כתובת התמונה>`. **אירוע:** `POST /api/event { "type": "supporter_gift", "supporter": "<שם>", "avatar": "<כתובת התמונה>", "mult": 50 }`. כללי ברירת מחדל (`/automations`): r20 מתנה מתומך → `fan_burst` · r21 ניצחון → `fan_mvp` · r22–r24 ‎×2 / ×3 / ×5 → `fan_burst` עם הכפל. הם פועלים רק כשהאירוע אומר מי התומך (`supporter`).
- **התמונה:** כתובת מהשרת הזה (למשל `/media/avatars/...`) או כתובת של שרתי התמונות של TikTok, שנמשכת דרך `GET /api/avatar?u=` (רק `https` ורק משרתי TikTok). תמונה בלי פנים (לוגו, ציור) נכנסת כעיגול; בלי תמונה בכלל: עיגול זהב עם האות הראשונה של השם.
- כמה תומכים ברצף **מחכים בתור** (אחד אחרי השני); אותו אפקט לאותו תומך פעמיים בתוך 2.5 שניות נחשב אירוע אחד. `/play/stop` עוצר ומנקה את התור.
- **בפאנל:** כרטיס "💛 אפקט לתומך" (שם + תמונת פרופיל מקובץ + כפתורי ×2 / ×3 / ×5 / ×50 / MVP). **קוד:** `AvatarHeads` ב-`fx/opponent.js` (גזירת הראש מתמונה) · השכבה `fan` ב-`fx/battle-stage.js` (`_fan`) · ההגדרות ב-`media/battle/heads.json` (`fan_burst`, `fan_mvp`; הקליפ המקורי `media/battle/extra/burst-gold.webm`). אפקט חדש באותו סגנון = קליפ נוסף על רקע שחור + רשומה ב-`heads.json`.

## הטלפון (ADB)
| כתובת | מה זה |
|---|---|
| `GET /fx/phone.mjpeg` | מסך הטלפון חי (המקור "טלפון" בפאנל); עם `?need=tiktok` — רק כש-TikTok פתוח |
| `GET /fx/phone.jpg` | תמונה אחת של המסך; עם `?need=tiktok` — רק כש-TikTok פתוח (אחרת 409 ושום דבר לא מצולם) |
| `GET /fx/phone-info` | איזה טלפון נבחר ואיזו אפליקציה פתוחה בו |
- כמה טלפונים מחוברים? נבחר לבד זה ש-TikTok פתוח בו. לקבע טלפון: `ADB_SERIAL=<מספר>` ב-`server.env`. גודל התמונה: `PHONE_SIZE=720x1600`.

## הגדרות
- `server.env` — הגדרות רגילות (פורט, כתובת ציבורית, מפתח Studio, מצב ניסיון).
- `.env` — **סודות** (Kling, OpenRouter, API_TOKEN). לא לשתף, להחליף אחרי מסירה.
